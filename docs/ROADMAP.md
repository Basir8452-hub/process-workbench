## 2. 已知问题

### 功能与体验

- 应用完全退出时不会后台推送；9:00 自动日报依赖应用运行，或在 9:00 后首次启动时补生成。
- 资讯默认使用必应资讯 RSS。若公司网络限制必应，需要在“资讯设置”中替换 RSS 源。
- 没有配置 AI 模型时，资讯只能生成原文摘要，无法生成分类摘要和 RAG 问答。
- 多人共用同一个 Windows 账号时，会共享同一份数据文件。

### 工程与发布

- 安装包未做代码签名，Windows SmartScreen 可能提示。
- 没有自动更新机制。
- Ant Design 6 的 `List` 组件存在弃用警告，不影响功能。
- 开发模式有 Electron CSP 安全警告。
- 历史打包目录 `release-v2` 到 `release-v7` 较多，交接前应清理，只保留最新产物或全部移出仓库。

## 3. 下一阶段优先级

### P0：交接与工程质量

- 初始化 Git 仓库，打 `v0.3.1` tag。
- 补充自动化测试：
  - `retrieveArticles()` BM25 检索
  - Excel 解析与导出
  - 日期/到期提醒工具
  - `normalizeStore()` 数据兼容
- 增加 GitHub Actions / 本地 CI：`tsc --noEmit` + `npm run build`。
- 清理旧 `release-*`、`dist`、临时脚本。
- 增加 `.env.example` 或明确“不需要环境变量”的说明。
- 安装提速：当前 Electron 等依赖体积大、安装耗时长；可配置镜像源（npmmirror）或提交锁文件后用 `npm ci` 加速。
- 安装包压缩瘦身：当前 electron-builder 未启用压缩（NSIS 默认不压缩），安装包约 105MB；可加 `"compression": "maximum"`（electron-builder 支持），预计可降至 70MB 左右，并显著加快安装器解压速度。

### P0.5：体验改进（2026-10-22 用户反馈）

- 待办事项提醒：三天内到期的待办也要提醒（当前只有"今天到期"和"逾期"两类）。
- 文件台账改为"归档"定位：当前是"审核"型设计（含工序/产线/复审日期），改为归档型，方便检索；去掉工序/产线字段，换成标签；去掉生效时间和复审时间字段（有需要再加）。
- 个人知识库卡片排版修正：标题应位于卡片横线上方，横线下方才是正文；当前文本过多时会超出卡片围框，需修正。
- 个人知识库导入类型扩展：支持表格、图片等常用文件类型导入（当前仅支持文本/文档类）。

### P1：业务模块扩展

- **托福英语学习（已上线 v0.4.0 的扩展功能）**：题库扩充与去重（目前 50 题、两日间约 1-2 题重叠，可扩充至数百题）、答题历史可视化（正确率趋势、薄弱题型）、错题本、生词本、每日推送提醒、听力/阅读题型扩充、AI 解析增强。
- **NPI / 工艺开发项目**：项目台账、EVT/DVT/PVT/MP 阶段、Gate 评审、交付物清单、试产跟踪。
- **产线 Qualify / 放行**：人机料法环测检查表、评分、整改项、放行记录、复审提醒。
- **降本与工艺优化**：改善项目、工时/材料/良率 baseline、收益核算、验证关闭。
- **OEM/ODM 工艺管理**：代工厂档案、能力矩阵、文件对齐、巡厂/audit 不符合项。
- **指标看板**：问题关闭率、平均关闭周期、重复问题率、NPI 达成率、放行准时率、降本达成率。

### P2：数据与安全

- 从 JSON 迁移到 SQLite（保留 JSON 导入导出作为兼容层）。
- AI Key 迁移到系统凭据库（Windows Credential Manager / Electron `safeStorage`）。
- 增加多用户档案切换：同一台电脑上不同人使用不同数据文件。
- 数据加密与自动备份校验。
- 代码签名与自动更新。

### P3：平台迁移

- **继续 Electron**：改动最小，适合当前 Windows 单机场景。
- **Tauri**：安装包更小，但需要 Rust + MSVC Build Tools，并重写 IPC。
- **Web / PWA**：适合浏览器访问和多设备，需要 IndexedDB 或服务端。
- **云端 SaaS**：适合团队协作，需要后端、数据库、登录和权限体系。

迁移时优先保留 `src/pages`、`src/components`、`src/types.ts`、`src/services/news.ts`；替换 `electron/` 和平台适配层即可。

## 4. 当前不建议做的事

- 不要在未加测试的情况下大规模重构 `AppStore` 和 RAG Prompt 逻辑。
- 不要把 AI Key 写入源码或提交到 Git。
- 不要在未确认需求前引入多人协同和云端数据库。
- 不要直接删除用户数据文件或旧备份。
